## Handoff through the current host

`GameplayHost` receives sequence-checked 512-frame stereo blocks from Node and admits them to its credit-controlled ring. The normal output branch opens RichAudio’s own WASAPI render client. `WasapiOutput` separately counts ring consumption and successful submissions, reads endpoint padding and samples `IAudioClock` with its correlated QPC timestamp. Submission advances when `ReleaseBuffer` succeeds. The host’s normal stop path stops and resets its own stream. The source code supplies useful landmarks for RichAudio’s stream, but it has no mapping to GTA’s native contribution intervals, and process termination can bypass that shutdown path. [Gameplay host](../src/acoustics/host/Windows/GameplayHost.cs) · [WASAPI submission and shutdown](../src/acoustics/host/Windows/WasapiOutput.cs) · [Windows audio clock](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition) · [Windows stream reset](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-reset)

A future common selection point needs the native vehicle and sound lifetimes, source/emission intervals, and the corresponding output intervals. RichAudio must have the complete correctly timed replacement at that point before withholding native output. PCM generation, ring admission, client submission and device playback are distinct events. The native side must use its original contribution when the selected interval is missing, late, invalid or expired. If the game accepts already spatialised RichAudio output, qualify that route against duplicate attenuation, Doppler and environmental processing.

Where separate render queues are unavoidable, establish a bounded mapping from both streams to a common output clock. Measure both submission-to-output delays, padding and downstream queued audio, clock drift and timestamp uncertainty. Include first and last output across activation, missing-block fallback, graceful stop and abrupt host loss. Ring and clock logs can locate candidate intervals. Claims about gaps or overlap also require an independently distinguishable output measurement under separate approval. Without that bound, the separate-queue route cannot qualify for takeover. Retain the existing buffer contract.

Map emission to output through each path’s actual delay. Tag replacement output and continuing tails by source generation and output interval so a fallback can distinguish an already committed contribution from PCM it can still discard. Define the allowed transition for already committed native sends and RichAudio tails before qualification. A blanket flush can truncate legitimate history, and an unchecked drain can duplicate a contribution during handback. A host heartbeat provides no output-interval guarantee.

| Failure | Required behavior of a future authority |
| --- | --- |
| Node producer exits, stalls or misses an interval | The surviving native selection point uses original output for the first interval lacking complete valid replacement. A block already queued remains subject to the measured handback bound. |
| External host terminates | The same native authority invalidates replacement ownership independently of host cleanup. Prove what happens to output already submitted by the failed process. |
| RPH managed controller unloads or lease expires | A native authority with independently verified residence and scheduling allows original output at its next defined decision point. Prove the exact unload ordering and that the authority still executes. |
| Vehicle or sound retires, or a handle is recycled | Retire the authority key for that lifetime. Reject delayed observations and grants. GTA’s own retirement remains authoritative, and a new generation starts on native output. |
| Native authority hangs, callback is invalid, native state is corrupted or GTA crashes | No independent recovery is established inside that failure domain. Managed cleanup and an external watchdog cannot restore a stalled in-game decision path. |

## Evidence required before an observer

The smallest useful input is a maintainer-supplied observer/diagnostic contract tied to the exact executable and RPH identities, or a separately authorised, read-only analysis of the exact executable restricted to this path. It must show the automatic vehicle audio owner’s create/update/retire call sites, the vehicle and sound lifetime linkage, the documented or evidenced ABI and scheduler, and the route from the sound and its children to allocation and mixing. It must identify which fields actually carry component provenance and whether an observation can occur without retaining invalid pointers or changing audio state. A maintainer can answer with the exact API and lifecycle guarantees or a metadata trace that proves the association. Version strings, a mixer slot or an unvalidated pattern match alone are insufficient.

With that binding, the first separately reviewed experiment is a bounded metadata trace of two existing Batis. Compare A’s and B’s continuous engine/exhaust through idle/load changes with an observed preserved auxiliary on A. Record owner and sound generations, child provenance, creation, update, retirement, route, timestamps and clock information. Record natural allocation/virtualization transitions if observed, with absent transitions remaining inconclusive. Reject the proposed contribution point if it combines targeted audio with an inseparable auxiliary or other owner. The trace would establish only the observed attribution and routing. Even an output-preserving hook modifies runtime execution and needs separate reviewed approval.

These validate the existing authored policy and disabled production registry. No native build or runtime test was possible under the evidenced interface.
