## Nearby scenes, continuity and timing

The opt-in coordinator reuses the existing `SpatialTileIndex02` to prioritise listener/source surroundings. It composes at most eight selected tiles with at most 128 finite surfaces and 32 unknown regions. Exact uncovered volumes remain explicit gaps; partial input cannot become complete coverage. Conflicting resource hashes, shared surface identities/materials, overlapping volumes and world/session/layout mismatches reject publication.

A dedicated Node worker prepares the union. Publication waits for its actual exit and requalifies the result against the original branded inputs on the separate control thread. That bounded recomposition has a measured cost; a checksum alone is not derivation or authority. Cancellation, timeout, invalidation and close join every worker and cannot publish an old world. Exact reuse avoids a new generation. The scene horizon contracts to the earliest tile **or surface** expiry, and expired cached scenes are withdrawn.

All of this is an explicit offline/background API. It adds **zero fixed PCM frames**, creates no event waiting queue and does not run on the game fiber or host callback. It has no ordinary gameplay caller. A future live controller must keep resource parsing, IO and this preparation/requalification outside the producer/render path. Existing dynamic-overlay contracts remain separate and unchanged; no live door or destruction state is invented by the static importer.

The explicit Bati scene setter changes geometry only. Source identity, grain cursor, dry samples and renderer source-history arrays remain intact through the tested scene and camera-generation changes. It preserves identical reflectors only under exact existing surface/material/configuration equality. It does not relax camera, expiry, generation, propagation or source freshness protections.
