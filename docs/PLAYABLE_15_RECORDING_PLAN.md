An engine-only or exhaust-only **post-acoustic stereo** stem is a further signal beyond the existing dry buffers. The production renderer currently accumulates emitters into its shared stereo output; it has no per-role stereo capture API. Its optional `directStem` renderer is a direct-path comparison, not an engine/exhaust separation, and the gameplay route does not enable it.

## Smallest credible preparation

For an offline genuine-trace investigation, an isolated analysis wrapper can copy the existing dry inputs once, retain the actual combined output, and feed the same prepared controls and masked original inputs into independent diagnostic renderers. Verify their settings/history/generations and compare their stem sum with the actual combined output, reporting any float-rounding or shared-limiter difference. This produces explicitly offline derived stems without altering the sealed candidate. The source controller must advance only once per original block.

Live dry and post-DSP stems require a new, narrowly scoped reviewed build: add an opt-in Node-side bounded copy queue at the existing source/output buffers, with file writing outside the render path, and bind it to the existing explicit recording permit/session. Extend recording lifecycle/finalization only enough to join that writer and include its files, completion/error state and hashes. Retain the existing host submission tap and loopback driver. Recording overflow must mark the affected evidence incomplete without delaying or replacing playback. No source-bank, renderer algorithm, gain, expiry or ownership change is needed for the basic dry/combined taps.

Use a single recording/session identity and an explicit producer timeline for every new tap: RA07 sequence, absolute producer-frame start, 512-frame count, 48 kHz rate, listener spatial generation, source identity/generation and exact stage/gain description. Existing `owned-index` already records producer-frame start, supplied frames and submission boundaries, enabling mapping across output blocks when those indices are valid. Dry emission and propagated arrival samples naturally differ in time. Map loopback separately from actual packet/host clock evidence; report uncertainty, discontinuities and missing start coverage rather than aligning by file start.

Size the shared byte/duration budget for the requested streams before approval. Two mono dry files plus combined stereo post-DSP, final stereo and 48 kHz stereo loopback total **184,320,000 sample bytes for 120 seconds**, exceeding the existing 134,217,728-byte default before metadata. A duplicated two-channel pre-acoustic file adds another 46,080,000 bytes. Reuse the dry pair as the pre-acoustic representation where suitable; choose an explicitly bounded recording duration/budget in the new proposal.
