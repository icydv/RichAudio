# WORLD10 independent benchmark evidence review

Codex reviewed my benchmark harness and evidence separately from their author. This reviewer authored the WORLD10 audio implementation, so this review does **not** count as an independent review of that audio code. The review used retained original-only artifacts and read-only source comparisons; it did not repeat the full performance measurements or access game assets, private banks, keys or endpoints.

The independent recomputation checked **21 artifact digests**, **352 measured children**, **55,104 WORLD10 blocks**, **597,794 nested spans** and **672 contention workers**. All checked strict deadline decisions, nested wall/CPU/GC arithmetic, portable mode summaries and **256 PCM/lifecycle comparisons** match the retained raw records. Every checked contention worker recorded readiness, a requested stop and a clean joined exit. The retained 14-test focused log also matches its published digest and records zero failures or skips. [Machine-readable review](../evidence/acoustic-world-10-independent-evidence-review.json)

My frozen-04 reports contain 128 processes and 19,968 render calls. Their prepared-plus-JIT arm has zero misses in 7,680 calls; the corresponding parent arm has 97. The frozen-05 prepared refresh has zero misses in another 7,680 calls. These are the reported results, without omitting the separate cold/preparation-only failures or earlier development failures.

The baseline ZIP contains exactly 118 original MJS files. Its extracted files match the ZIP bytes. All 118 differ from the parent Git blobs only by Windows CRLF conversion, and match parent `8a995c8c8f5e7ab1461af64e756f30eafb7667a3` after newline normalization. The archive and measured-file digests remain the exact byte identities; this is not a claim that the export bytes equal the Git blobs.

Two evidence limitations were identified:

- The historical reports bind production snapshots and the top-level profiler, but the root-loaded `Processing10.mjs` input fixture and profiler helper closure were not contemporaneously bound. No input drift was observed; complete measurement-time harness/input closure remains unqualified for those reports. A future binding correction requires new artifacts and cannot retrospectively seal them.
- The historical summarizer did not include instrumentation mode in baseline selection. Twenty-four final and six historical comparisons therefore select a baseline from the other instrumentation arm. Their recorded dry/stereo blocks and source lifecycle still match exactly. Future summaries should prefer the matching arm and explicitly identify the selected baseline.

Neither result establishes private-bank coverage, long-session real-time safety, GTA-load behavior, WASAPI continuity, physical latency or audibility. My 10.6667 ms deadline is unchanged, and retained failures remain findings.

The subsequent **pinned-06** controls address the input-closure finding prospectively. Their 122-file snapshot includes the executed profiler, authored input fixture and accounting helpers. Both baseline and prepared children load the same frozen input modules and retain matching pre/post input bindings. Codex independently verified all snapshot members and all **96 children**, **15,360 blocks**, **113,328 nested spans**, **192 contention-worker exits** and **48 matching-instrumentation PCM/lifecycle comparisons**. The prepared-plus-JIT arm retains **zero misses in 7,680 calls**, while its newly measured parent baseline retains **107**. My largest prepared textured instrumented block is **10.6417 ms**, leaving only **0.02497 ms**, about **25 microseconds**, below the unchanged deadline. It is the first genuine source block in a direct-scene, four-contender trial. Construction is 0.1452 ms and synthesis 7.4601 ms; the measured GC overlap is temporal evidence, not a complete causal explanation. This thin observed margin is **not robust real-time headroom**. The prepared-arm result excludes banks that exhaust the preparation budget: those explicitly retain the original immediate cold constructor and its known deadline risk. Data validation for an unprepared bank can be deferred until that cold activation; actual validation exceptions are not caught as budget exhaustion.
