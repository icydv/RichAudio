# ACOUSTIC-WORLD-06: my startup-prewarming architecture

My target is now explicit: **prepare all qualified supported static geometry before normal gameplay, including places I have never visited**. Runtime raycasting supplies validation and dynamic observations; it does not discover the basic static world by driving around it. No CodeWalker GUI, Blender or manual export is introduced as an ordinary product dependency.

Codex implemented an executable offline coordinator over my existing resource inventory, cache builder/store, background conversion worker, finite acoustic solver, stock source/renderer and SoundMap. This separate draft stacks after PR #86 at `7efaaab17497a36a352c468558e3dfea145fe4ea`. Earlier PRs, real measurements, private captures and consumed candidates remain unchanged. **Actual installation-wide discovery, genuine Enhanced compatibility and a native pre-gameplay/loading-screen gate are not qualified by this work.**

## Feasibility and the real-input boundary

The [public-source investigation](ACOUSTIC_WORLD_06_FEASIBILITY.md) distinguishes cache indexes from collision geometry. `cache_y.dat`-family records provide identities, extents, layers and interior proxies; manifest/YMF, DLC setup/content/patch/changeset metadata and actual resource owners supply additional dependencies and conditions. Those indexes do not contain all collision triangles or establish runtime activation. The development reference separately loads YBN resources for collision queries. It can obtain unvisited static resources from archives without moving a player, but its reverse-engineered behaviour is not a supported Enhanced mesh API or a redistributable product licence.

The practical direction is a qualified **headless static reader plus runtime state validation**, with all qualified static conditional variants represented before selecting live states. Broad metadata completeness, Enhanced decoding capability, ownership, permitted provider use and redistribution remain unresolved for a public product. Historical repository results are retained as historical offline evidence with their original Gen9/mount/placement limits. Codex did not reopen their private assets or repeat their access.

My [next experiment](ACOUSTIC_WORLD_06_READ_ONLY_PROPOSAL.md) asks a broad question in one bounded batch: join the complete declared base/DLC/custom metadata domain into effective world resources and dependency ownership, including missing, conditional, uncached and unsupported partitions. It does not select another building, read another encrypted header or use visit history. The smallest input mode uses an existing complete decoded metadata bundle; a direct installed-read variant needs a legitimate provider and a finite reviewed archive/member/listing closure. The proposed limits are not access permission. Exact inputs, paths/hashes, provider/runtime, containment and approval are still missing, so there is no executable protected candidate or launch command.

## Executable full-catalogue preparation

[`sealStartupCatalogue06`](../src/acoustics/world/startup-catalogue06.mjs) seals metadata-only descriptors of existing qualified inventory pages. It checks global tile/member identity, mount order, cross-page spatial overlap, bounded metadata and explicit discovery closure. Pages retain local resource plans and dependency digests; a change in an unrelated page does not change an unchanged tile's plan. The current finite prototype supports at most 256 pages, 64 tiles per page and a 4 MiB catalogue. These are capacity bounds, not evidence of complete installed coverage. An incomplete source domain remains indeterminate.

[`StartupAcousticCoordinator06`](../src/acoustics/world/startup-coordinator06.mjs) has **no player position, radius or visited-set input to startup `run()`**. It enumerates every declared eligible tile. The existing bounded builder is invoked at each tile's own centre, one tile and one conversion worker at a time. This uses its existing conversion/cache path without restricting preparation to the player. Source buffers can be supplied lazily for one page/tile; unchanged cache hits require no source-buffer load or reconversion. Only metadata and bounded selected geometry are retained, not the entire world's meshes.

Work is not counted complete until the tile is persisted and reloaded against its exact expected artifact binding. Progress distinguishes discovery, cache checking, conversion and verification. Its percentage is **verified persisted eligible tiles / declared eligible tiles** after the denominator is known. Actual world coverage remains unmeasured. Unsupported plans, unknown regions, failed work, partial decoded geometry, runtime activation and first-run completion have separate status. A cache query that later detects corruption withdraws that tile's readiness rather than preserving a green result.

Callback boundaries have finite deadlines and cancellation. A hung provider, store or checkpoint promise is quarantined; late results cannot publish readiness or trigger fallback conversion. The coordinator reports unresolved operations and closure unknown, and blocks further work through that failed boundary. A JavaScript timeout does not terminate arbitrary OS IO or preempt synchronous host code. Real archive providers still require independently supervised process containment. Worker shutdown and final checkpointing have separately bounded cleanup budgets. No GTA main thread, game fiber or audio callback is involved.

## Persistent cache and recovery

[`StartupTileStoreRouter06`](../src/acoustics/world/startup-tile-store06.mjs) routes stable tile IDs to shards of the **existing versioned integrity-checked resource cache**. It preserves that format, qualification checks and artifact bindings. A full page no longer prevents a changed tile from acquiring a new version beside unrelated completed tiles. Aggregate byte, shard and per-tile version quotas are enforced; initial startup measures the private cache once and subsequent publication accounts for new bytes. The router memoizes at most 16 path/budget store objects and retains zero geometry. It assumes one trusted control host, not cross-process quota arbitration.

[`StartupCheckpointStore06`](../src/acoustics/world/startup-checkpoint06.mjs) saves closed, versioned, content-addressed generations through create-new atomic publication. It stores only catalogue/page/plan/artifact identities, never source payloads or geometry authority. Restart requires a separately retained trusted control-host digest; it never scans for an implicit latest checkpoint or lets a self-hashed journal authenticate itself. Automatic protection/provisioning of that local trust anchor remains product integration work, not a manual-hash requirement in my intended user experience.

The coordinator intersects prior artifact bindings with current per-plan identities and verifies actual cache files before reuse. Missing/corrupt journals, source changes, incompatible builds, missing/corrupt tiles, storage errors and quota failures remain visible. Completed generations and interrupted bounded output are retained; no consumed evidence or old cache is silently deleted. The prototype has finite version/generation quotas and no automatic garbage collector. Exhaustion needs explicit recovery/maintenance; it cannot be reported ready. A cancelled preparation can persist verified progress and resume without rebuilding those tiles. This establishes restart semantics, not power-loss durability on every filesystem or hostile-filesystem containment.

The [sparse spatial index](../src/acoustics/world/startup-spatial06.mjs) serializes catalogue bounds and identifiers, then rebinds the exact bytes to the current qualified catalogue. A bounded grid query selects at most eight already-prepared tiles near the listener and intervening source corridors, with omitted/unprepared regions explicit. It performs no conversion or filesystem IO and never treats a box or empty query as acoustic evidence. The existing background cache load and scene composer remain responsible for finite geometry and unknown gaps. Corridor candidates are conservative metadata scheduling, not propagation paths; existing solver distance/history limits are unchanged. The original rehearsal persists and reloads the index before selecting its never-visited remote tile.

Runtime epoch tracking records state metadata only. It does not implement native IPL/door/window activation, conditional-geometry variant selection or MLO acoustic routing. Qualified provider and renderer integration must supply those relationships; unknown variants/topology stay unsupported. Callback input allocation and control-host memory remain trusted producer responsibilities. The existing conversion worker has its own bounded heap; a real archive provider needs its separate process memory and IO limits rather than inheriting a JavaScript callback's timeout.

Existing startup-hook compilation is not proof of its earliest live execution stage. No unknown memory patch, forced fade/pause, unsafe raw-frame native or busy-loop loading gate was added.

Its RichAudio-owned bottom-right preview explicitly says the native GTA label is unchanged. It is not connected to player control. A qualified prelaunch bootstrap is a controllable future entry point; a post-initialisation readiness view is another candidate after its actual callback contract is verified. ## SoundMap and the never-visited acceptance result

The [read-only coverage adapter](../tools/soundmap/worldcoverage06.mjs) projects bounded windows of declared tile bounds/status and unknown areas. The overview rectangles are coverage bounds, never invented walls. Only an explicit cached tile enters the existing finite-geometry layer. The current detailed adapter is qualified on original RSC fixtures; actual installed resources and MLO topology remain unqualified. Dynamic doors, IPL/interior activation and movable objects are labelled separately. Current collision tiles do not persist fabricated room/portal connectivity.

The existing solver and telemetry produce source/listener poses, direct/reflected paths, distance and delay. Exact model/session alignment is required to overlay them. The viewer does not solve acoustics or grant authority. Browser mutation, recording, replay and host routes are closed; unavailable recording/context/replay controls are hidden before scripts run.

The critical original acceptance test prepares **12 separated tiles across three inventory pages**. No tile is visited during preparation. Before recording the first simulated visit, it reads the far tile's persisted finite surfaces and calculates a reflection with **zero conversion workers**. No actual street, building, metre calibration or perceptual evidence follows.

Earlier local and hosted spikes remain findings without a measured cause. No endpoint latency or audible improvement is claimed.
