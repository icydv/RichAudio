# MIGRATION-SHVDNE-01 — RPH dependency map

I am making SHVDNE the primary managed integration route while retaining my working RPH adapter and historical experiments as rollback references. Codex inspected actual source at migration base `8f1900c` and added the new adapter in the isolated migration worktree. The audio engine, retained assets and existing acoustic algorithms are preserved. This inventory describes implemented replacement boundaries and the capabilities still awaiting parity; it does not declare an RPH-free live release qualified.

## Parity boundary

The new route compiles a standalone SHVDNE script plus the existing external host without an RPH assembly reference. It provides a concrete framework boundary, lifecycle, player/NPC and camera observations, native invocation, menu adapter, preparation/SoundMap connections, host IPC and isolated profile-control probe. Automatic host startup is prepared behind the existing package/identity contracts and remains disabled in the default smoke configuration.

It is not full live functional parity. The exact game/API/ASI/Script Hook V combination, memory-backed RPM and other operating-state fields, vehicle-pool identity/cost, UI behavior and reload/containment need live admission. Per-wheel/suspension/contact-material acquisition and older RPH sensing/logger commands are not ported here. Since default RPM is unavailable, default wire output cannot drive a claimed vehicle-audio parity demo; this is an explicit data-quality gate. Native suppression and independent recovery remain unimplemented Gate A requirements. These are reasons to retain RPH, not reasons to replace any existing acoustic engine component.
