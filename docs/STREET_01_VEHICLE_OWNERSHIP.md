# STREET-01: vehicle continuity and selective native ownership

My [focused passive diagnostic](STREET_01_PASSIVE_TELEMETRY.md) and [single-session proposal](STREET_01_PASSIVE_SESSION_PROPOSAL.md) continue this work without enabling takeover. Codex is preparing the candidate offline; the prior closed live approvals remain closed.

I still require one Bati's engine/exhaust to be replaced selectively. STREET-01 does **not** satisfy that requirement yet. The implementation remains additive, and native takeover remains disabled. Codex has not launched GTA, suppressed a native component or reused a closed PLAYABLE approval for this revision.

## Changes in the actual main-mod adapter

Codex extended `Playable.Rph.cs`, the normal main-mod entry path, rather than the isolated MENU-02 entry point. Normal startup now calls the existing world-preparation supervisor, which validates its sidecar and queues bounded background work; unload requests cancellation. Missing or disabled configuration remains explicit, and the hook alone does not establish a completed installed-world map. A tracked vehicle now binds the full returned pool value, index, counter, opaque address and a per-acquisition serial. Its prepared acoustic bank context remains attached to that source lifetime. Driver attachment is a separate observation: dismounting no longer changes the source generation or selects a new bank merely because the listener is outside the vehicle. The retained vehicle's actual `IsEngineOn` getter continues to determine the reported running flag. An invalid entity, failed getter or expired observation provides no invented engine-off observation.

The bridge rechecks the returned lifetime after the source getters. Ordinary handle recycling cannot inherit the old source. Counter wrap with indistinguishable address/value reuse remains an uncertainty; this change does not claim an unlimited entity-lifetime authenticator.

Camera tracking now uses the existing `CameraListenerTracker`. A measured cut is discarded and starts a new spatial generation. A later independent camera acquisition can recover; the vehicle's operating/source generation remains independent. Story-scope loss invalidates the camera baseline while retaining ordered listener sequence/generation. There is no interpolation through a teleport, refreshed timestamp, extra playback queue or changed 512-frame block.

The gameplay wire has optional `riderAttached` and `riderViewAttached` booleans. Old packets omit them and therefore cannot qualify rider-local airflow. The first reports the actual current local driver relationship; the second additionally requires gameplay-camera rendering and vehicle-follow-camera observations. A detached view can therefore retain the same moving vehicle source while withholding rider-local turbulence. Source airflow velocity comes from `Vehicle.Velocity`, never camera differences. Native coordinates remain `native-unverified`, with the engine's existing declared one-unit/metre assumption; these changes do not establish physical speed calibration.

The new camera queries are declared in the [GTA native corpus for gameplay rendering](https://github.com/citizenfx/natives/blob/master/CAM/IsGameplayCamRendering.md) and [vehicle-follow camera state](https://github.com/citizenfx/natives/blob/master/CAM/IsFollowVehicleCamActive.md), checked by Codex on 5 November 2026. Their declarations do not qualify Enhanced/RPH return semantics on my installation. A query failure withholds rider-view attachment. The genuine installed getters, view association, dismount audibility and source continuity still need an explicitly approved integrated live test.

Closed SHV handoff evidence and its player-driver-only qualification policy are unchanged. This source revision does not silently promote the old SHV proof to detached or post-dismount operating-state authority. The earlier rejected RPH ratio remains a real qualification gap; Codex has not rescaled an out-of-contract getter to manufacture a usable observation.

The completion pass found a separate identity defect in normal `Capture`: an invalid ratio removed the independently retained vehicle, so the next offer acquired a new serial even when the full pool identity had not changed. Codex changed that branch to withhold the invalid observation while retaining its pool owner and original bank context. It does not update the last valid pose or timestamp. Short recovery can retain its source generation; an actual gap above 250 ms still crosses the existing generation boundary. Missing/dead/recycled entities still retire. This fixes a source-lifetime defect, not the invalid ratio getter.

The actual normal route remains `PlayableEntry.Capture` → `GameplayRuntime.Publish` → the owned latest-snapshot pipe → `GameplayHost` → `Run-Gameplay.mjs` → `StockGameplay`. Its operating point still originates in the unmodified RPH `EngineRevolutionsRatio` getter and is rejected outside `0..1`. The separately compiled SHV handoff entry bypasses normal Capture; its historical successes do not make this normal route a working installed telemetry feed.

## New disabled passive telemetry route

Codex implemented a new diagnostic path rather than reopening an old PLAYABLE lease. `src/telemetry/StreetTracked01/Producer.cpp` registers a dormant SHV script. Only the separately compiled `STREET_TRACKED_DIAGNOSTIC_01` RPH entry can begin the reviewed passive configuration. Its sidecar defaults disabled, requires exact module/game/RPH file bindings, and forbids audio and native sound mutation. The ordinary product has no such compilation symbol and gains no second entry point or native provider.

The SHV fiber first acquires its own native vehicle handle from the current player Bati and checks its opaque SDK address against the independent RPH peer. It then retains that native handle across dismount and observed engine-off states. Each reading brackets the original raw ratio bits with vehicle existence/model/address/running observations and QPC times. The diagnostic's independently acquired RPH peer retains full pool value/index/counter/address and reads its own unscaled ratio; it does not replace normal Capture. The comparer rejects changed identities, replay, foreign sessions, stale/future evidence and excessive peer skew. Neither side treats an RPH pool value as an SHV handle. The API uses one bounded latest record and a single source lifetime, with no automatic rebinding.

These interfaces come from the [public SDK header](https://github.com/scripthookvdotnet/scripthookvdotnet/blob/3a0b4786ea8cff050fbccf7993a2cfedc8d4a64f/source/loader/sdk/inc/main.h) and the [pinned Enhanced native declaration](https://github.com/alloc8or/gta5-nativedb-data/blob/424fb51b089049a9fbcebcc641500b1d44d255b4/natives_gen9.json#L112332). Codex's read-only export audit found the seven required public imports in the supplied installed SHV binary. That establishes interface presence, not runtime behavior. [Microsoft documents](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps) the QPC/Stopwatch time basis; the adapter additionally checks an actual native clock return inside its managed call bracket. It [retains and releases a module reference](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulehandleexw) while calling its exports.

Seven original-only scenarios exercise the actual new native registration, dormant script startup, real C ABI, RPH entry, retained peer, comparer and stop transitions against authored SDK/native responses. They include disabled startup, wrong module binding, dismount plus observed stop, RPH counter recycling, native address change and two controlled stop/acquisition races. Replay, stale/future clock and foreign-session controls also retain rejection. The authentic RPH SDK compiles the production entry separately; a production native candidate is compiled and linked but never loaded. The reviewed receipt is `.local/street01/tracked-diagnostic-f34acac591004381b26399aa68f0d041/validation.json`. Earlier fixture failures remain preserved. The corrected fixture bounds each child at ten seconds.

Independent source review found and corrected two transitions that could revive a stopped diagnostic. The native state now uses compare-and-exchange transitions that preserve its retired state. An armed module receives an explicit process-lifetime pin before activation; ordinary reference release cannot unmap a still-scheduled SHV callback. The background managed observer waits at most 1,000 ms for the loop-exit flag and retains its ordinary reference if that observation is absent. That flag is not an external SHV join or proof that the callback has executed its final return instruction. The supported diagnostic requires whole-game exit before replacement/removal: it makes no safe hot-unload or in-process restart claim. This limited passive lifetime policy is not recovery of an owned native sound profile.

This is a concrete prepared diagnostic route, not qualified normal telemetry. The next discriminating measurement requires separate approval to load these newly bound diagnostic artifacts, record simultaneous raw RPH/SHV returns for the same acquired Bati, dismount while retaining it, and observe running/off transitions. It must preserve source times and report the getter, lifetime or clock boundary at the first failure. The diagnostic cannot start an audio host, supply PCM or enable takeover. Existing producers and closed leases remain unchanged.

## Why selective native replacement is still blocked

Codex rechecked primary interface documentation on 5 November 2026. The [RPH Vehicle property surface](https://docs.ragepluginhook.net/html/Properties_T_Rage_Vehicle.htm) and [method surface](https://docs.ragepluginhook.net/html/Methods_T_Rage_Vehicle.htm) do not supply an established engine/exhaust-only gain with exact original-state recovery. Those public pages are older than the target runtime, so their absence is scoped documentation evidence, not proof that no internal route exists.

The [profile-assignment native](https://github.com/citizenfx/natives/blob/master/AUDIO/ForceUseAudioGameObject.md) accepts a vehicle and named game object. Its declaration supplies no getter for the current effective override, independent expiry/restore guarantee or exact-stack custom-profile registration contract. A vehicle argument alone does not prove two-identical-vehicle isolation or preservation of auxiliary components. Codex did not try an empty/invalid profile. The [whole-vehicle silent declaration](https://github.com/citizenfx/natives/blob/master/VEHICLE/SetVehicleSilent.md) explicitly reports collateral door/horn effects and therefore fails my selective requirement. No broad mute or physical-engine modification was implemented.

The smallest credible remaining route is a uniquely registered, component-isolated audio metadata graph, selected only for the identified vehicle. That is an inference from the available profile/metadata interfaces. Before it can become an enabled adapter, it needs all of the following evidence:

- A supported loader/registration mechanism on this exact Enhanced/RPH stack, within the approved dependency and distribution scope.
- An effective component/dependency graph distinguishing the continuous engine/exhaust represented by RichAudio from transmission, induction, backfire and the auxiliary sounds GTA retains.
- Exact active-profile/baseline readback or another independently verified restoration baseline, plus two-same-model instance isolation.
- A recovery authority that survives the relevant renderer/plugin/controller failures. A cleanup callback or a controller that must execute its own timeout cannot establish fail-open crash recovery.
- Separately approved audible native-only, prepared, replacement and restored comparisons, retaining horns, tyres/road contact, collisions, radio, ambience and the neighbouring Bati.

My newly approved read-only Bati metadata scope can refine graph attribution, but reading a graph cannot establish these runtime controls. No modified proprietary profile, archive patch, native-suppression package or unsupported loader has been produced. The existing ownership prototype remains accurately labelled a policy fixture; no additional hypothetical state machine is offered as selective replacement.

Codex retained the first field-only survey, whose empty `HashReferences` arrays were an adapter gap because this Core exposes those references as properties. The corrected private survey at `.local/street01-installed/bati-graph-02/resolved-catalog.json` now retains the actual property references for one Bati, three game-record summaries and four granular sound roots. It verifies ten unique engine/exhaust stream references against two actual AWC metadata tables, without decoding PCM. The joined worker took 29.602 seconds and peaked at 1.348 GB across its owned Job. Catalogue digests and raw derived tables remain private.

That corrected graph identifies distinct transmission and upgraded induction references, alongside normal/upgraded exhaust-pop and limiter-pop references. The vehicle record also retains horn and collision references. My existing granular bank covers the selected engine/exhaust acceleration roots; it does not establish ownership of transmission, induction, upgraded pop layers or those auxiliary sounds. Zero and shared fallback references do not prove that a component is absent, silent or active at runtime. The profile identifier remains an explicit model-name fallback inference because the model's audio-name field is empty, and actual runtime selection remains unobserved. These findings make the component attribution more precise; they do not establish selective suppression, same-model instance isolation or recovery after controller failure.

## Completion-pass registration and dependency audit

Within the new read-only scope, Codex extended the actual resolver to traverse typed public fields/properties, nested references and scalar values, with a depth-eight/256-record ceiling. The joined decoder took 72.565 seconds and peaked at 1,472,618,496 bytes. It produced 256 nodes and 3,097 candidate-reference edges bound to seven actual REL metadata files. The traversal hit its record ceiling: 488 queued records were omitted, 468 nonzero references remain unresolved and 666 projection gaps are explicit. These counts include opaque data and bounded nested projections; they are not 666 proved missing audible layers. The graph's closure flags remain false. The raw graph and bindings stay private at `.local/street01-installed-completion01/resolved01/resolved-catalog.json`; no PCM was decoded.

This graph resolves the transmission root as a variable-block sound and the upgraded exhaust-pop root as a wrapper leading to the limiter-pop multitrack root. It also retains category/curve references, including shared fallback roots. Raw volume/pitch scalars are stored with their declared types and unknown units. A numeric zero is not interpreted as silence, and a shared wrapper is not interpreted as proof of runtime activation. The existing engine/exhaust bank still does not establish ownership of those overlapping components.

The same run read one existing `mpbiker` DLC's `content.xml`/`setup2.xml` registration metadata. It exposes `AUDIO_GAMEDATA`, `AUDIO_SOUNDDATA`, `AUDIO_DYNAMIXDATA`, `AUDIO_SYNTHDATA` and `AUDIO_WAVEPACK` declarations. This proves an installed content-registration example, not the selected base Bati's bootstrap registration or a uniquely owned profile. The selected Bati graph is still rooted in the base update game REL.

The [OpenRPF author's page](https://www.gta5-mods.com/tools/openrpf-openiv-asi-for-gta-v-enhanced) describes loading modified archives from a mods folder. It does not document a runtime component-gain, active-profile readback or independently expiring per-instance assignment API. Codex's separate on-disk audit of the supplied `OpenRPF.asi` found file version `0.1.0` and 157 named C++ utility exports; none established those audio interfaces. The page currently advertises `0.3`, so its current description is not exact-version qualification of that supplied binary. The authentic SDK still supplies declarations rather than the installed getter implementation, and the compressed runtime container remains unreadable through the reviewed metadata reader. No loader was updated, initialized or bypassed.

The remaining selective experiment is now narrower. First, an approved private uniquely named audio object must be registered through a proven Enhanced content path while retaining every auxiliary reference. Registration and name resolution must be distinguished from component isolation; a whole-object assignment changes auxiliary sounds too, as the [SHVDN primary source documents](https://github.com/scripthookvdotnet/scripthookvdotnet/blob/main/source/scripting_v3/GTA/Entities/Vehicles/Vehicle.cs#L238). Only after that, changes confined to the continuous engine/exhaust branches can test isolation against an untouched neighbouring Bati, native-only control and exact restored control. The unresolved graph and unknown scalar semantics currently prevent producing a supported selective profile.

Exact baseline recovery is a separate missing capability. The available assignment declaration returns no prior effective override and exposes no expiry guarantee. An external renderer timeout cannot invoke a failed game adapter, and a plugin `finally` cannot recover after its own failure. The decisive API evidence would be supported effective-profile readback plus compare-and-restore/expiry, or an independently surviving in-game restoration authority with demonstrated failure-domain coverage. Until that exists and separately approved failure/isolation measurements pass, I leave native takeover disabled; this pass does not add another hypothetical ownership controller.
