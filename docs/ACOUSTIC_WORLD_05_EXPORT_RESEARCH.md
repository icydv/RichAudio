## Why launching Explorer is a larger access scope

The pinned [`Program.Main`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/Program.cs#L19-L104) checks the GTA folder before opening menu/Explorer/world forms. Its [`EnsureJumpList`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/Program.cs#L107-L165) can change Windows shell/settings state. A nominal export session is therefore not automatically a host-wide read-only process.

[`ExploreForm.Init`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/ExploreForm.cs#L175-L247) loads keys, refreshes the tree and prepares caches/material/scenario data before selection. [`RefreshMainTreeViewRoot`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/ExploreForm.cs#L716-L775) enumerates descendants. The ordinary [key-loader branch](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/Utils/GTAKeys.cs#L248-L268) may read a game executable and uses embedded data. These are public-code findings, not executed operations. Edit mode off, a camera position or selecting one visible building does not bound this startup IO.

The real selected-file operation is [`ExportXml`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/ExploreForm.cs#L2353-L2424), which invokes [`GetFileXml`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker/ExploreForm.cs#L1504-L1530) and writes XML. A future approved GUI operation would select each exact file individually, use **Export XML**, write each to a new private destination, and avoid edit/import/save/asset-converter/batch operations. This describes the method; it is not a runnable or approved session. All startup source/dependency reads and shell/profile effects would first need their own explicit, independently reviewed scope. No such closure has been established.

## A smaller library conversion when raw exports already exist

The source provides direct supplied-buffer APIs: [`YmapFile.Load(byte[])`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YmapFile.cs#L77-L103), [`YtypFile.Load(byte[])`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YtypFile.cs#L173-L182), and [`YbnFile.Load(byte[])`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/FileTypes/YbnFile.cs#L33-L60). [`MetaXml.GetXml`](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/MetaTypes/MetaXml.cs#L181-L198) handles map/type objects and [the YBN overload](https://github.com/dexyfex/CodeWalker/blob/485d56bec00262ed7fa472261cce7bbc6202b96e/CodeWalker.Core/GameFiles/MetaTypes/MetaXml.cs#L237-L242) delegates to the bounds writer. A fixed wrapper can receive three already-approved buffers, explicitly select/restore the Gen9 reader state, and return three XML buffers without starting `Program`, `ExploreForm`, `GTAFolder` or a key loader.

This is a candidate method, not an implemented genuine-resource export authorization. The public Core assembly still contains other APIs; merely choosing it does not establish containment. A future raw-buffer converter needs fixed reachable operations, bounded decompression/XML output, independent process/OS restrictions and a reviewed runtime closure. It must not build or rewrite resource binaries. The earlier original-format XML tests demonstrate selected static fields on original fixtures; they do not authenticate genuine resource provenance, arbitrary native parsing or Enhanced installation compatibility.

Separately, Codex's [original-only generator](../tools/New-CodeWalkerBuildingFixture05.ps1) uses the actual library builders/readers/exporters for a closed box with eight vertices, twelve outward triangles and eight independent API readback controls, including four non-coplanar controls. Three XML exports and six selected static DTO roundtrips pass. This fixture supplies missing 3D/corner regression input to the existing pipeline; it is not a Los Santos asset. Its private public-source build is not an official released GUI binary or real-input containment qualification.

## Selecting the first suitable building

Selection must come from an independently approved record or future discovery operation, not an invented asset name. My first target needs one ordinary `CEntityDef`, one supported base archetype and actually associated external triangle collision. I will avoid MLOs, runtime entity sets, breakables and multi-entity assemblies. A matching filename or a `physicsDictionary` value is not proof of the collision relationship.

An ordinary exterior can have shared world-space YBN collision or embedded drawable bounds. The new decoder can preserve an explicit local/world declaration, and inspection applies the corresponding transform; that does not verify ownership. Embedded bounds, ambiguous/shared ownership or an oversized world collision file cannot be forced into a one-building local subset. Retain the limitation and stop for a reviewed target/scope change. No suitable triplet is promised before those identities are known.

The export must preserve source placement, stored quaternion, XY/Z scale, geometry centers and composite matrices. Independent world-coordinate controls must challenge translation, rotation and nonuniform scale, including vertical variation. A CodeWalker transform oracle can check an independent implementation of those calculations; it does not establish physical metre calibration or live activation by itself. Unqualified geometry may be inspected under its supplied-input status, with unknown ownership/coverage visible. It must not become an acoustic surface merely because XML parsing succeeded.
