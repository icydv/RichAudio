# PLAYABLE-15 recording recovery: latency diagnostics

This change prepares measurements for one separately approved Bati demonstration. No live latency is measured by this work. The owner's 250–500 ms impression remains subjective. The established first live result is unchanged: 27.832 seconds of submitted PCM, a failed startup recording, and independently verified restoration.

The existing sound, source mapping, source expiry, gains, DSP and buffering are retained. In particular, the 100 ms control delay, eight-block/85.3333 ms startup reserve, and previous 22 ms endpoint buffer describe different parts of the pipeline. Adding them does not measure end-to-end delay: startup reserve is an initial fill target, actual occupancy changes, endpoint buffering overlaps submitted audio, and software submission is earlier than physical output.

## Event contracts and bounds

`gameplay-control-delivery` uses `host-Stopwatch-QPC`, with a maximum of 2,400 retained rows per host. `host-producer-block` and `producer-block-timing` sample every eighth 512-frame producer block (85.3333 ms between sampled block starts), at most 1,500 rows each. A sampled block can still identify source-state age precisely within its brackets; an unsampled response can only be narrowed to the sample interval unless a waveform or other retained evidence resolves it.

`producer-block-timing` contains `producerFrameStart`, `frames`, `nodeClockDomain: node-performance-ms`, `nodeFrequency: 1000`, render start/end, processing duration, stdout completion, latest accepted sequence, source target time, fixed control delay, and at most two actual selected source brackets. Each bracket retains id/generation, left/right sequence and observation ticks, frequency, interpolation and operating value. The observation clock is explicitly `host-Stopwatch-QPC` and its basis is identified as gameplay vehicle pose. In the actual SHV adapter the vehicle tick is the RPH peer pose acquisition midpoint, **not** the native operating-state acquisition timestamp. Join these listener sequences to private handoff journal `gameplay-frame.lineage` to obtain `sourceBeforeTicks`/`sourceAfterTicks` and `minimumHostTicks`/`maximumHostTicks` for true native operating-state delay. A vehicle-pose age alone cannot establish it. The event also retains snapshot receipt/acceptance Node times and the host command's original write-before QPC/frequency. Its outer recording row is explicitly in host QPC at stderr receipt; its inner fields remain in Node time.

Do not subtract a Node millisecond timestamp from host QPC. For one event, Node snapshot receipt occurs after host `snapshotHostWriteBeforeQpc`; Node stdout completion occurs before host stderr receipt. After converting the *rates* to common units, these observations bound the clock offset rather than establish an exact point. Preserve the resulting interval and intersect only compatible, monotonic intervals from the same process/session. Scheduling and pipe delay widen it. Native acquisition additionally retains its independent measured native→RPH mapping bounds from the original journal. Different frequencies, expired mappings, missing rows or conflicting bounds make a result unavailable.

Every additional event is prepared on the existing host control/PCM-reader/stderr workers or on the Node producer, outside the native endpoint callback. `OwnedOutputTap`, `PcmRing` and `WasapiOutput` are unchanged. Node logs are capped at 1,900 characters, at most 1,500 rows, and offered only below 16 KiB stderr pending bytes. Omitted rows are counted in worker status. The host records retained/rejected producer rows, control rows, ring rows and superseded snapshots in `host.json`. The existing 128-row diagnostic queue, per-row/total recording bytes, private storage cap, owner permissions and final drain remain enforced. Queue overflow remains an explicit recording failure. There are no new stems or microphone permissions.

The existing render deadline counter still observes every generated block. The new sampled processing records are additional evidence, not a substitute for that cumulative counter. No physical output-time metric is added to the callback.

## Device-free validation

`node --test tests/Test-Gameplay.mjs` with the existing full nine-player-plus-Bati-NPC private package passed all eight tests with zero skips. The new test compares every Float32 byte of 112 stereo output blocks with timing diagnostics enabled and disabled; output is identical. Fourteen sampled rows retain exact producer frame identity, source interpolation endpoints/operating values and clock domains. Existing ownership, retirement, expiry, mapping, source-headroom, acoustic path, geometry and pause tests passed in the same run. Running the all-mappings regression against the deliberately Bati-only package first failed its nine-mapping precondition; it was rerun against the correct full-map fixture without changing the assertion.

`tools/Test-GameplayLatency.ps1 -Candidate <fresh corrected private package>` exercises the actual Bati runtime, secured pipe, Node source/renderer, RA07 decoder, ring, device-free sink, post-gain tap and WAV writer with authored observations. It checks that sustained PCM and all three timing event types survive finalization, actual selected source brackets survive, sampled producer blocks join retained host submissions, time order and caps hold, saved preferences remain unchanged, and no endpoint opens. Its result is a private fixture receipt; it is not live GTA acquisition, endpoint loopback alignment or a measured latency budget. The authoritative completed run and candidate hashes belong in the recording-recovery validation receipt.

No buffer changes should be selected from this offline timing. After the approved follow-up yields a continuous paired capture, first determine which stages have direct measurements, which have interval bounds, and which remain unexplained. Only then consider a separately reviewed latency change.
