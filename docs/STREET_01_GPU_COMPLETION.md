# STREET-01 GPU pages and silent comparison files

I have source implementation and bounded original-fixture evidence for GPU visibility beyond 128 finite supports. I do not have complete audio deadline qualification, a qualified audible main-mod candidate, live activation evidence or gameplay/FPS measurements. The separate cold NPC history failure remains unresolved.

Codex extended the existing vendor-neutral DirectCompute broadphase to at most 4,096 supports. Each dispatch uses a two-dimensional segment/page grid, with 128 supports per page. One active-prefix readback returns every page for a segment batch. The existing exact CPU predicate still resolves the original global support identities, openings, finite footprints and unknown regions. There is no support truncation, per-page synchronous readback or new PCM buffer. The existing bounded helper ownership, deadline, cancellation and exact CPU fallback remain.

The original version-1 request/response ABI stays available for at most 128 supports. Larger requests explicitly negotiate version 2 and its segment/page mask layout. A legacy helper keeps the entire larger workset on CPU. The helper's maximum owned buffers total 4,587,536 bytes; a maximum result contains 2 MiB of masks. Capability alone does not qualify acceleration.

Large immutable geometry is packed on the existing installed-scene preparation worker. Adoption retains the actual-Worker capability boundary, exact observation key/count/origin/length checks, ordinary owned `ArrayBuffer` backing and a bounded private copy. The producer does not transform or hash thousands of supports during adoption. A missing preparation uses the exact CPU route. The packed geometry is also bound to the exact immutable support array before dispatch.

## Original controls and measured limitations

The explicitly selected private helper ran on the RTX 2080 Super. The focused hardware correctness receipt is [gpu-pages-bulk/receipt.json](../.local/street01-completion/gpu-pages-bulk-af3a2c8c952647a8ab5f08edcaefcfe9/receipt.json). The maximum request's measured round trip was 7.9953 ms, including helper execution of 3.9962 ms. Its diagnostic request deadline was 100 ms, so this is correctness evidence rather than audio headroom acceptance. A cold 128-support request took 9.3228 ms.
