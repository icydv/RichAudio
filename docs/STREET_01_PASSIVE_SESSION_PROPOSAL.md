Proposed outer limits are 600 seconds from sole launch dispatch to offline Story/Bati readiness, at most 10 seconds to close the console before arming, at most 120 seconds of native observation, three seconds for managed writer completion, and 180 seconds for normal exit, within 913 seconds total. ## Gameplay observations

Within the single 120-second maximum, the phases are:

1. Acquire the identified Bati and observe stationary engine-running state for about 15 seconds.
2. Rev gently, then move ordinarily at low speed for about 30–40 seconds, retaining plausible changes rather than calibrated physical RPM claims.
3. Dismount once and continue observing the same retained vehicle where valid. The diagnostic records what GTA does; it does not assume dismount leaves the engine running or turns it off.
4. Observe a genuine running/off transition if it occurs through the agreed ordinary gameplay. No script changes engine state, vehicle behavior or attachment. If no transition occurs, that phase is explicitly unobserved.
5. Retain the first genuine source-loss boundary if one occurs; otherwise the fixed observation limit retires the diagnostic. A limit retirement is not evidence of entity loss or engine shutdown.
6. Exit GTA/RPH normally and verify complete closure before restoration.

Every phase reports whether both peers identify the same full lifetime, whether raw operating values are finite/in-contract and change plausibly, whether observations are fresh with acceptable peer skew, whether identity survives attachment changes, and whether running-state changes can be distinguished from tracking loss. Unsupported or unobserved phases remain unknown. Private telemetry records are not audio recording.

The verdict identifies the first failing getter, identity, timing, output or lifecycle boundary, rather than treating successful loading as qualification. Raw values and original QPC brackets remain available. Invalid RPH values are not rescaled, missing rows are not engine-off events and old observations cannot refresh current state. A useful native result can identify a candidate operating source without qualifying the normal main-mod route automatically.

An invalid RPH operating value disqualifies that interface for the affected phase; it does not automatically end the independent SHV measurement while identity and timing remain valid. Structural association/timing loss or a failed native target call ends the lifetime. This distinction permits the experiment to explain the existing RPH getter failure without hiding a separately usable native result.
