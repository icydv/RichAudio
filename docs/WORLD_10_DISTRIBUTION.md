# WORLD-10: my minimal distribution boundary

I want the Core API component to contain exactly the necessary precompiled vendor DLLs and my own adapter. My new default validation route does not rebuild upstream Core, copy its source or publish the WORLD08/09 research package. Those research tools and historical PRs remain intact.

[`distribution10.mjs`](../src/acoustics/world/distribution10.mjs) and [`Package-CodeWalkerRuntime10.mjs`](../tools/Package-CodeWalkerRuntime10.mjs) implement exact-file component packaging. With no independent standard-binary audit/review, they return `blocked` before opening any supplied DLL directory. No upstream source, vendor download, key initialization or automatic repair occurs.

The prospective runtime is `CodeWalker.Core.dll`, `SharpDX.Mathematics.dll`, `SharpDX.dll` and `RichAudio.CodeWalkerApiAdapter10.dll`. The [API report](WORLD_10_CODEWALKER_API.md) explains each dependency, framework requirement, measured research footprint and licence boundary. Its four-DLL research total of 5,045,248 bytes is not an official product-size or distribution qualification claim.

Before packaging, an externally pinned independent review must bind every audited DLL's exact length and SHA-256, authenticate an unmodified dexyfex artifact, exclude proprietary bootstrap/game assets/keys and identify the exact dependency closure. Research augmentation markers, unknown embedded resources, extra DLLs, unreviewed references or missing public resource APIs fail closed. Current research metadata cannot pass this gate. Metadata names and hashes alone cannot prove vendor authenticity or the absence of every embedded secret.

The review must also bind `CodeWalker.Notice.txt`, `CodeWalker.Readme_Src.txt`, `CodeWalker.PERMISSION.txt`, `SharpDX.LICENSE` and every additional applicable third-party notice. `FBX.LICENSE` is mandatory when the exact Core review reports FBX code present. The upstream notice attributes FBX conversion under GPL; selected API use does not erase binary-wide third-party obligations. This source-free component profile refuses a review requiring vendor-source redistribution. The gate needs an explicit independent obligation/completeness decision for the exact binary and a hash of its evidence; counting notice files does not settle licensing. My permission statement does not replace those obligations or authorize modified binaries. Codex has not contacted dexyfex or initiated another permission workflow.

Review fields are trusted, externally supplied assertions under a separately verified receipt hash. They are not signatures, legal advice or an automatic proof that someone has performed a review. The packager continues to report `legalClearanceVerified:false`, `installedWorldQualified:false` and `deployed:false`.

For accepted reviewed inputs, the tool reads only exact named files with fixed byte/aggregate caps, hashes and pre/post file metadata. It never enumerates a directory or copies an adjacent GUI, helper, `magic.dat`, source tree or asset. It writes a fresh current-checkout `.local` component and its manifest last, never overwrites an existing result and leaves any partial failed result for inspection. Link/hardlink rejection and hash checks are appropriate to controlled software staging; Node pre/post checks are not atomic Windows no-follow containment for protected game inputs. This tool is not a private-resource reader.

The packaging tests use original dummy DLL bytes and simulated review metadata. They demonstrate allowlist, tamper, notice and failure mechanics only. No authentic standard Core artifact or distributable Core package exists in this increment. The new API envelope also requires a separately reviewed bridge into existing provider authority once a standard artifact is qualified; changing the envelope's kind or setting a caller hash cannot confer that authority.

The next real-data boundary is [my blocked genuine-building proposal](ACOUSTIC_WORLD_10_READ_ONLY_PROPOSAL.md). No new game/capture/key/tool access, launch, endpoint, deployment or merge is authorized.
