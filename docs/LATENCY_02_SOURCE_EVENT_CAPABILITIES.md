# LATENCY-02: source events and native coexistence

I want transient events to avoid the continuous Bati history and producer queue. I do not yet have a verified, timestamped gunshot-emission adapter for my Enhanced/RPH stack. GTA remains the primary source for gunfire, impacts and explosions. This increment supplies an offline admission gate and original authored impulses, with real direct and reflected event generation blocked. It does not install an adapter or suppress native sound.

FiveM does offer more specific network facilities. Its [server event documentation](https://docs.fivem.net/docs/scripting-reference/events/server-events/#weaponDamageEvent) describes `weaponDamageEvent` as a request to damage a remotely owned entity; its `damageTime` is associated with the network timer. `startProjectileEvent` describes projectile creation. These are not every locally fired hitscan round or a host-QPC/audio mapping. Pinned [framework source](https://github.com/citizenfx/fivem/blob/9f0e34e1cbdfc34fd05079416791f01938279097/code/components/citizen-server-impl/src/state/ServerGameState.cpp#L4936) also parses a network `explosionEvent`, including an audibility flag. Canceling or modifying a network game event is not verified selective audio suppression and may alter gameplay. I do not use these routes, switch frameworks or infer an Enhanced/RPH adapter from them.

## Admission and clock contract

`src/acoustics/events/acquisition-capability.mjs` is deliberately disconnected from game adapters. Its immutable production capability is `BLOCKED`; caller-supplied verification flags cannot enable it. Both direct synthesis and reflected augmentation of real gunshots/impacts/explosions are denied, so there is no speculative extra native shot or echo.

Only explicit `authored-fixture` mode with a locally branded, matching session can admit `authored-impulse` under `authored-fixture-only` authority. The brand records the synthetic experiment; it is not a native-support certificate or a security boundary. Serialized/copied capabilities, wrong sessions and real event categories are denied. Source identity, generation, sequence and output-frame validation remain separate descriptor responsibilities.

Timing has distinct fields:

- `acquisitionBeforeQpc` is an optional acquisition-call bound; `observationAfterQpc` is the host observation/receipt bound, with explicit `qpcFrequency`.
- `occurrenceLowerQpc` / `occurrenceUpperQpc` describe occurrence uncertainty only when independently known. The current native poll/callback-receipt descriptions keep both `null`. They never substitute a poll midpoint, previous poll or receipt for emission.
- The positive fixture supplies its own ordered occurrence interval on `authored-fixture-QPC`, no later than its authored receipt. It may precede the acquisition call. It does not claim native sample accuracy or invent a QPC-to-output mapping.

A future event adapter would need exact-stack schema/provenance, stable source identity/generation and event sequence, measured loss/duplication behavior, occurrence-clock semantics and bounded mapping to the host clock. Acquisition and callback-receipt brackets must survive even when occurrence time is unavailable. A precise host read time alone cannot reconstruct when a projectile left the weapon. Nearby observation-to-submission targets exclude that unmeasured acquisition delay.

Direct replacement additionally needs verified per-source/component suppression, exact restoration and failure recovery under the existing [native ownership policy](NATIVE_AUDIO_OWNERSHIP_01.md). GTA's primary blast, damage and auxiliary sounds must continue until that gate is met. Even reflections-only coexistence needs a separate attribution/timing/content proof; this increment does not assume that adding a delayed shot is harmless or correctly separated.

The focused command is `node --test tests/Test-EventAcquisitionCapability.mjs`: nine device-free tests cover immutable production denial, forged claims, real-category rejection, session/brand isolation, null native occurrence time, malformed timing and preserved authored intervals. No native adapter calls, game/endpoint access, installed assets or vendor inquiries occur. Research and SDK receipt fingerprints are in [the sanitized evidence](../evidence/latency-02-acquisition-research.json).
