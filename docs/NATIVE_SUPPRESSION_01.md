# NATIVE-SUPPRESSION-01 — one player idle-wave contribution

My immediate target is the Bati player's granular `Channel4` (`engine_idle`), not the whole engine family. Codex selected a matched private-resource experiment: preserve the wave, replace its PCM with an original identifiable marker, then replace that same PCM with valid zeros. An isolated SHVDNE script requests those profiles on one newly created Bati and requests `BATI` again on the same surviving lifetime. **No result in this task demonstrates suppression in GTA.** The decisive missing observation is whether the private player branch actually plays the marker, disappears under its matched zero-PCM variant, and returns on normal release.

The source work started from clean local `f47522fdb18bd8f5c49397aa15e8f4a27c0e74cc` on `feature/migration-shvdne-01`. This work supersedes the earlier recommendation that the private horn marker must precede every engine experiment. That recommendation was an experimental choice, not an engine dependency. The earlier packages, consumed approvals and failures remain evidence.

## Experiment driver and restoration limits

The new script is separate from the production integration and renderer. It starts disabled. Exact on-disk game/API/DLC hashes are compiled into its private build; a worker checks them before enabling the experiment. No game calls occur on that worker. Native calls run only on the script callback thread.

Ctrl+Shift+F5 creates two Batis once per script load. Identity is the full handle, Bati model, script ownership and a distinct decorator token. Lost identity stays lost. A is left, B right. No existing vehicle can be adopted. With my ped driving stationary idling A and B also idling, empty and stopped, Ctrl+Shift+F6 arms the next fixed phase and F7 applies it within ten seconds. The sequence is stock observation → preserve → marker → silent → marker → preserve → `BATI`. Every phase requires a new manual arm; there is no automatic advance or arbitrary profile argument. Admission is checked immediately before the setter after native context queries. F8 records context. The B vehicle is never assigned a profile.

F9 stops progression and requests known `BATI` on the same surviving A when its identity and safe Story context still hold. The request is consumed before dispatch and a throwing restoration is not retried. A deferred restoration can be explicitly requested after returning to a safe stationary context. The final normal sequence also requests `BATI`. Both are native invocation evidence only until I hear and record normal sound on that same vehicle. F10 performs separate empty/stopped retirement after the restore request has returned; deletion is not counted as restoration.

The experiment has a fixed ten-minute deadline from spawn request, checked by progressing script callbacks, and a five-second model-load bound. At expiry it stops progression and attempts the same scoped restoration. This is not an engine-enforced lease. Script abort/domain unload makes no game calls on the potentially different domain thread. Controller stall, abort, unload, native failure or game failure can leave the persistent experimental assignment. In that case I end the offline session normally; this contains the experiment but does not earn M4 or M5. Renderer/IPC failures are outside this native-only candidate because no replacement renderer is started. A worker/journal failure stops new assignments while normal F9 restoration remains available. Evidence is bounded and written off the game callback.

The controlled baseline assumes no competing audio writers on these newly spawned stock vehicles. The known Trainer is temporarily parked for the approved run; no other managed scripts are admitted. This does not restore arbitrary custom overrides, observe the complete effective graph, arbitrate concurrent mods or detect an adversarially copied decorator. Stock-named custom content can differ; controlled file identities and listening baselines are required. Production recovery/readiness and replacement-tail handoff remain unchanged and unqualified.

## PRIVATE03I correction

The latest retained PRIVATE03I attempt failed in candidate manifest admission, before an audio result. The real manifest is 2,863,378 UTF-8 bytes and decoded characters; the previous serializer used its 2,097,152-character default. The new manifest-specific reader bounds input at 4 MiB bytes, 3 MiB decoded UTF-16 characters and eight hierarchy levels (the actual manifest uses three). It hashes and parses the same retained bytes, uses strict UTF-8 and bounds malformed-input error text. Other small-message parsers keep their limits.

The regression compiles the actual production supervisor without fixture symbols, invokes its real `Validate` path with candidate mode, and passes the unchanged production manifest. Its 26 checks include the historical failure reproduction, byte/character boundaries, multibyte/BOM inputs, malformed/truncated/oversized/deep input, wrong identities and retained notice/deadline/restoration requirements. Original failures and consumed approvals remain unchanged. [Microsoft documents character length](https://learn.microsoft.com/en-us/dotnet/api/system.web.script.serialization.javascriptserializer.maxjsonlength?view=netframework-4.8.1) separately from the [hierarchy limit](https://learn.microsoft.com/en-us/dotnet/api/system.web.script.serialization.javascriptserializer.recursionlimit?view=netframework-4.8.1).

The idle experiment deliberately does not inherit the old horn experiment's manifest/session or its five-second notice and 80/100/140-second phase gates. Its independently reviewed scope uses the exact candidate files, visible in-game phase, explicit manual arm/release, fixed ten-minute window and normal rollback. This is an explicit protocol revision, not a silent extension of an old approval. No old approval authorizes this test.
