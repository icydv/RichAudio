# NATIVE-AUDIO-OWNERSHIP-03

Gate A remains blocked. I require the first playable alpha to replace continuous native engine and exhaust on one Bati, preserve the rest of GTA audio and return safely to the original state. This pass checked the loader and recovery interfaces against the retained Enhanced 1.0.1158.16 and RPH 1.132.1428.17748 target. All new observations are public-source or retained reference-SDK evidence.

## Registration without replacing the update archive

- **OpenRPF 0.3.** The release page lists OPEN and encrypted archives as read-compatible under mods-folder redirection. Version 0.2 made the cache bypass automatic and removed the bundled `dsound.dll` according to the changelog. Version 0.3 declares compatibility for 1013.17+ builds. This improves archive visibility and gives a candidate for exact-build loader review. The author material provides no standalone private DLC registrar, per-member DLC-list overlay, audio-registry query or audio unload contract. Its archive format support does not make the NG base archive editable by my OPEN-only writer. The retained 0.1.0 fingerprint and observed NG header are historical evidence for that installation. Compatibility of 0.3 with my exact ASI chain is unmeasured. [OpenRPF release and changelog](https://www.gta5-mods.com/tools/openrpf-openiv-asi-for-gta-v-enhanced)
- **RageOpenV v1.0 is a distinct archive-free candidate.** The published tag resolves to `f742117a5e8ccc359bf3b4644c6bce7dad77cc7a`. Its source includes a boot-time loose virtual device for the effective DLC list and standalone pack, with a separate Enhanced startup branch. The example concerns a map pack. The author subsequently described loose-file support as unfinished and NVE's use of it as unsupported. That leaves exact-build precedence, fallback for untouched files, support status and audio metadata registration open. RageOpenV's own installation instructions treat it as a replacement for OpenRPF. This is a useful maintainer question, separate from upgrading to OpenRPF 0.3. [Tagged source](https://github.com/Chiheb-Bacha/RageOpenV/blob/f742117a5e8ccc359bf3b4644c6bce7dad77cc7a/src/hooks/CustomDevice.cpp), [v1.0 release](https://github.com/Chiheb-Bacha/RageOpenV/releases/tag/v1.0), [maintainer support statements](https://www.gta5-mods.com/scripts/rageopenv)
- **Other pack tooling.** The Enhanced pack creator still directs the author to the DLC list inside the update archive. The CodeWalker-based CoreFX installer describes copying the target archive and converting that copy to OPEN. A separate author's Enhanced NG research reports a DLC-list edit that booted a cloned pack, but that approach changes the update archive and the report does not exercise audio registration. Simple Mods Loader advertises per-file inputs and automatic archive construction. Its published description does not specify this private audio registration, precedence or unloading contract. FiveM data-file mounters remain a separate runtime. [Enhanced pack creator](https://www.gta5-mods.com/tools/dlc-pack-creator-enhanced), [CoreFX installer](https://github.com/cryleak/CodeWalkerProjects#how-installation-works), [NG researcher's results](https://github.com/alain0308t/gta5-enhanced-rpf7-ng/blob/main/README.md), [Simple Mods Loader](https://www.gta5-mods.com/tools/simple-mods-loader-enhanced), [FiveM data-file contracts](https://docs.fivem.net/docs/game-references/data-files/)

The runtime chain still needs an effective startup list that names the private pack, a resolved device and startup change set, and a positive audio-registry result for the private object and dependencies. The retained Marker A bytes establish packaging. Mount visibility, game audio-object resolution and safe unload require separate evidence. Codex did not build a new overlay or change either loader.

## Effective state and recovery

The pinned Enhanced corpus still lists `0x4F0C413926060B38` as a vehicle and name setter returning `void`. The Enhanced ScriptHookVDotNet fork at `d8e474fb2779f12a0c04282645d561a1d675ec77` exposes the same setter on `Vehicle`. The reviewed declarations provide no supported getter or restore token for the effective object and active override. Horn sound identifiers and model metadata supply different facts. The named declarations leave unlabelled and internal engine interfaces unresolved. [Pinned Gen9 declarations](https://github.com/alloc8or/gta5-nativedb-data/blob/424fb51b089049a9fbcebcc641500b1d44d255b4/natives_gen9.json), [Pinned Enhanced Vehicle wrapper](https://github.com/Chiheb-Bacha/ScriptHookVDotNetEnhanced/blob/d8e474fb2779f12a0c04282645d561a1d675ec77/source/scripting_v3/GTA/Entities/Vehicles/Vehicle.cs#L145-L166)

Codex extended the opt-in retained SDK reader to inspect recovery declarations without loading the assembly. The authentic reference is 1.124.1393.17586. It declares public `AppDomainPool.RequestNamedAppDomain`, `GetNamedAppDomain`, `GameFiber.StartNew` and `Game.UnloadActivePlugin`. All 12 inspected recovery rows have zero RVA. A named domain is a credible place to ask about an independent authority. The declaration does not establish the RPH scheduler, native invocation from the other domain, or survival of an unload or crash. RPH's preliminary public docs say native calls require a game fiber. An external Windows process cannot replace a missing live game-side native path. The Enhanced ScriptHookVDotNet documentation describes a separate tick thread for compatibility, which likewise supplies no original-state capture or restore contract. [RPH GameFiber documentation](https://docs.ragepluginhook.net/html/T_Rage_GameFiber.htm), [Enhanced ScriptHookVDotNet scheduling notes](https://github.com/Chiheb-Bacha/ScriptHookVDotNetEnhanced#downloads)

The best alternative is an **engine-owned, frame-local route or expiring contribution override for the selected vehicle's continuous engine/exhaust**. It could leave the original profile and bank selected, keep stock contributions for horns, transmission, tyres and collision, and use the native route by default when an authenticated replacement frame or lease is missing. It needs a supported per-voice identity and a fail-open contract enforced by the engine after the controlling callback or domain stops. A detour that can stay resident after its controller fails does not supply that guarantee. Entity mix groups expose entity/group membership, script sound IDs address script-created sounds, and FiveM voice submixes target voice. No reviewed supported route attaches these to automatic per-vehicle engine and exhaust contributions. [Pinned Gen9 declarations](https://github.com/alloc8or/gta5-nativedb-data/blob/424fb51b089049a9fbcebcc641500b1d44d255b4/natives_gen9.json), [FiveM voice routing](https://docs.fivem.net/docs/scripting-manual/voice/)

## Smallest next discriminator

The next step is the public interface question, prioritizing effective state and fail-open lifetime semantics. If a maintainer identifies an actual read-only observer, bind it to the exact game and SDK first. Observe two already existing same-model lifetimes with independently established different effective states, including a pre-existing override. Require observed base and effective identity, explicit override provenance, distinct stable lifetimes and original observation times. Reject stale evidence and verify natural retirement or recycling only if it occurs. An absent override control makes that part incomplete. The observation has no assignment, new mount, spawns or playback.

For registration, obtain a release-specific affirmative answer for a standalone loose-list route and an observable audio-registry result. A future reviewed boot test would distinguish the loader reading the loose list, private device selection, and positive resolution of one private record plus a nonexistent-name negative control. A change to the installed loader or archive would require separate approval. The current evidence does not support sealing that experiment, and it does not support a suppression trial.
