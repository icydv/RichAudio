## Native boundary

The strongest concrete precedent is the Cfx **owner-side sound creation boundary**. The reviewed `MumbleAudioEntity::MInit` explicitly creates a persistent `audSound` under its own audio entity with a named resource and `audSoundInitParams`. It attaches a position and environment context, can select a submix, attaches an externally supplied 48 kHz mono stream and starts it. `MShutdown` explicitly retires that sound. The owner and role are known because the Cfx extension creates and tracks the source. The reviewed `GenerateFrameHook` uses a custom ring ID to request more PCM from that known Cfx owner. It supplies data to the game; the observed Cfx clock granularity and ring are specific to that integration. [Pinned Cfx sound creation, playback and retirement](https://github.com/citizenfx/fivem/blob/5c3065c261fb3ba82032fee6803f247198fec221/code/components/extra-natives-five/src/NuiAudioSink.cpp#L1435-L1630)

The companion `GameAudioState.cpp` mixer code has a later view of existing wave-player slots. It checks active/reference state, generates or skips samples, reads the wave player's sample position and handles finished or freed slots. That can tell an integration about a player it can already identify. The reviewed loop supplies no semantic vehicle owner, engine/exhaust component tag or proof that a slot exists when an upstream scheduler declines to allocate a voice. Submix operations give a route for the owned input and do not demonstrate isolation of automatic vehicle contributions. [Pinned Cfx mixer processing](https://github.com/citizenfx/fivem/blob/5c3065c261fb3ba82032fee6803f247198fec221/code/components/gta-core-five/src/GameAudioState.cpp#L164-L288), [Pinned Cfx submix controls](https://github.com/citizenfx/fivem/blob/5c3065c261fb3ba82032fee6803f247198fec221/code/components/extra-natives-five/src/NuiAudioSink.cpp#L82-L201)

The first useful Enhanced target is the automatic **vehicle audio owner's semantic create, update and retire boundary before physical mixer allocation**. It must preserve the vehicle/session and voice lifetimes, component and event/record provenance, source clock and original route. A wave-player index, metadata hash, model or tracker position alone cannot carry that association. CodeWalker establishes Bati asset and REL graph relationships. The shared player/NPC exhaust branch, shared idle dependencies and unresolved synth/preset routes still prevent mapping every live voice by hash alone. The retained Cfx files were re-fetched at the pinned revision and matched the historical copies by SHA-256. Their legacy build branches and internal layouts do not establish a provider for Enhanced 1.0.1158.16 and RPH 1.132.1428.17748. Whether automatic logical creation precedes Enhanced distance culling is unknown. A callback that requires an allocated player cannot report a source whose voice was never allocated.

The potential observer still needs an exact-build lifecycle and threading contract, including clock definition, lifetime expiry and safe detachment. Its audio-thread path would need bounded, preallocated event transfer with no synchronous IPC, logging, bank work or geometry. Overflow must preserve native audio and mark the affected observation unknown. Binary layout drift, pooled IDs, lost retire events, unknown component routes and failure inside the game process are material risks. No native C++ integration or event transport was added. There is no qualified provider to measure or bind.
