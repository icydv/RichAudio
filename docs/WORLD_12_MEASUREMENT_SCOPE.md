# WORLD12 measurement scope

My parent is exactly PR91 at `3d0642df9588aa46721efd85712fd2ba07446345`. My block size remains 512 frames at 48 kHz, with a strict **10.666666666666666 ms** deadline and the additional **8 ms maximum-block headroom target**. Functional success, PCM identity and percentiles cannot replace either maximum-duration finding.

Codex retained the original WORLD11 reports and failed hosted run unchanged. WORLD12 uses separately named original-only snapshots and reports; its fresh parent is the WORLD11 candidate, not WORLD11's earlier PR90 baseline. No WORLD11 count is pooled into WORLD12 acceptance.

The versioned WORLD12 profiler carries forward the reviewed held-child process controls, actual affinity readback, owned CPU contenders, streamed Node executable bindings, source closure checks, memory/output/lifetime guards and no-retry matrix termination. The main design crosses parent/candidate, instrumentation off/on, plain/textured authored PCM, direct/wall scenes, normal/restricted-four logical CPU masks, zero/two owned contenders and two repetitions: **128 children /21,504 blocks per runtime**, 10,752 blocks per implementation. A separate 16-child control compares existing data preparation with/without existing authored throwaway JIT work in wall scenes without added contenders. It changes no product warmup behavior.

Both Node22.23.4 and Node24.19.0 run against the same final frozen closures. The public runtime SHA-256 identities are retained in the [WORLD11 scope](WORLD_11_MEASUREMENT_SCOPE.md), checked against the actual executed files before/after and at the held child gate. Runtime populations remain separate. Runtime order, CPU model, available logical CPUs and applied masks belong to the actual reports. Four allowed logical CPUs do not reproduce cloud hardware, physical cores, SMT, V8 startup pools or game load.

WORLD12 adds common **outside-timer** phase/history and path bookkeeping. Each active source's dynamic voice state is hashed after each rendered block: phase, clocks, RNG, selected plans and their Set order, heads/joins, boundary state and statistics are retained; immutable input PCM/interval/feature tables are covered by the separately bound authored input and source closure. Undefined, nonfinite values, negative zero and typed-array types have explicit encodings. Every block also hashes the complete selected direct/reflected path controls. Missing hashes fail comparison. Focused parent tests additionally compare complete enumerable voice/renderer state and future PCM suffixes.

This stronger bookkeeping changes allocation/cache exposure from WORLD11. It is identical in the new parent/candidate and instrumentation controls, is outside the common render envelope, and is not a product queue or a claim about an unobserved OS dispatch interval. The new helper is included in each **128-member** frozen closure and in the summarizer's before/after working closure. Raw reports retain every block, per-block PCM/history/path hashes, source eligibility/retirement/reacquisition, counters, actual runtime bindings and owned process closure.

Instrumentation-off starts no phase wrapper, inspector, GC observer, heap probe or CPU counter. Instrumentation-on retains nested intervals, validated exclusive-child unions, signed quantized CPU residuals, GC temporal unions and bounded V8 samples. Inclusive phases are not added as independent costs. Temporal GC overlap, sampled V8 frames and wall-minus-CPU cannot establish why a particular block missed; there is no OS scheduler trace or genuine GTA workload.

The final local raw audit found five negative V8 sample intervals. A post-measurement summarizer-only amendment explicitly leaves those sample timelines unqualified, retains signed data unchanged and preserves every wall/phase value and gate. Its new executed helper closure is bound separately from the old summarizer inside the original snapshots. Original final01 derivatives remain unchanged; authoritative final02 reports add only this diagnostic qualification and derived metadata. Four pure reporting controls pass separately on Node22/Node24; the full earlier local wrapper contains 41 new Node tests and does not retrospectively include those four. The final hosted wrapper selects all 45.

The inherited timeout diagnostics are a separate fixture-only experiment. Authored holds verify surviving stage observations and cleanup under the existing lifetime limits; they do not identify the cause of the original hosted failure. Fresh hosted validation runs only after independent review, with full functional and processing gates kept separate. Separate Node22 and Node24 jobs retain separate artifacts; a failed job does not cancel or retry the other runtime's independently selected condition. If inherited validation stops, later WORLD12 tests, snapshots and matrices are reported as unexecuted for that job.

No private bank, real captured archive, key, game executable or installed resource is read. Endpoint underflows, physical latency, actual Bati-bank timing and long-session GTA performance remain unmeasured. My calibration, grain behavior, buffers, queue stages, reflections, Doppler, default settings and LOW-LATENCY-01 architecture are unchanged. The [prepared CodeWalker API request](WORLD_11_CODEWALKER_API_REQUEST.md) remains unsent, and its minimal integration/dependency boundary remains unchanged.
