Candidate 07's UI REPL referenced `process.hrtime.bigint()`, but that environment has no `process` global. Execution stopped before host spawn. The operator then submitted the listener command independently of that failure, exhausting its sole connection attempt. The engine was not exercised. Its closed result and independent restoration remain unchanged.

`tools/listening/run.mjs` now runs through the explicit bound **node.exe**, outside the UI REPL. It imports `performance` from `node:perf_hooks`, owns the host child, records elapsed times/events and preserves the first failure. It validates the candidate hash, bound inputs, executable, cwd, exact reviewed arguments/settings and fresh deployed-attempt approval before permitting execution. `--validate-only` reads inputs without starting workers or opening endpoints.

The host's existing `RichAudio shared output: … Commands: … Maximum 60 seconds; gain 0.2` line occurs after output readiness and required listener `pipe.Start()`. Alongside the actual child `spawn` event and live process handle, it establishes **transport starting**. It is not proof of a connected or accepted listener. No named-pipe probe is made. A fresh qualified solver frame from a new producer stream separately confirms listener acceptance before emission or recording.
