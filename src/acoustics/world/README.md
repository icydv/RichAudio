# Installed collision import foundation

`tools/Export-InstalledCollision.ps1` reads one exact YBN entry through the user's existing trusted local CodeWalker dev46. It scans a supplied game-relative archive, never writes to the game/parser roots, rejects output outside this checkout's ignored `.local` directory, and bounds decoded bytes, nodes, vertices, polygons and traversal depth. Windows PowerShell 5.1 and Node are required. `-LoadKeys` uses the existing parser's key loader; no key or vendor binary is copied into the repository. `-HashArchive` verifies a SHA-256 before and after reading; without that switch the receipt explicitly records the weaker length/mtime check.

Provide `-GameRoot`, `-CodeWalkerRoot`, `-Archive` and the full catalogue `-EntryPath`, including the archive chain. Output has a private normalized JSON document, one resource directory, a `receipt.json`, bounded binary chunks and an `index.json` published last. An existing resource directory is rejected, so choose a fresh output directory for another run. No extracted geometry is committed, packaged or uploaded.

The adapter retains decoded vertices, each geometry's `CenterGeom`, masked triangle vertex indices, box indices, material slot, native material type and both packed material words. Child transforms are checked against `ChildrenTransformation1`, falling back to `ChildrenTransformation2` or the parser's identity default. Conversion adds `CenterGeom` exactly once, then applies transforms from the leaf through its ancestors using the SharpDX row-vector convention. Up to eight vertices per geometry are checked against the actual local parser's `GetVertexPos` result in the immediate parent's coordinates. Synthetic tests independently exercise nested translation, rotation and scale; a parser oracle alone cannot prove world placement.

Native box polygons store four alternating diagonal corners. The importer reconstructs their three edge vectors and eight corners, then emits twelve outward-wound face triangles. It preserves rotation and skew instead of substituting an axis-aligned box. This basis agrees with the publisher's [Renderable.cs](https://github.com/dexyfex/CodeWalker/blob/master/CodeWalker/Rendering/Renderable.cs) `BoundPolygonType.Box` rendering path. Normals are recomputed from the final transformed triangles; zero-area triangles have a null normal and are counted explicitly.

The primary API reference is the publisher's [Bounds.cs](https://github.com/dexyfex/CodeWalker/blob/master/CodeWalker.Core/GameFiles/Resources/Bounds.cs), specifically `BoundGeometry.GetVertexPos`, `BoundComposite.Read`, `BoundPolygonTriangle.vertIndex*` and `BoundMaterial_s`. The local DLL's public members and actual asset parsing were verified; the public development branch is explanatory evidence, not a claimed exact source revision for dev46.

The binary format is original: 24-byte header (`RACMESH1`, UInt32 LE version 1, stride 96, record count, reserved zero); each record contains nine Float64 LE coordinates, then six UInt32 LE values: material type, node index, polygon index, material Data1, material Data2, material slot. Each chunk contains at most 8,192 triangles and has a SHA-256 in the index. The 64-unit grid conservatively references every triangle-AABB cell; triangles spanning more than 512 cells use an overflow list. Queries return candidate chunks, followed by their AABB screen. They are a broad phase, not ray tests or an acoustic simulation.

All output is labelled `resource-root`, `unresolved-static-vs-archetype-local` and `triangle-and-box-surfaces-incomplete`. YBN coordinates alone do not prove whether a resource is a world-static mesh or an archetype-local asset. Spheres, capsules and cylinders remain explicitly unsupported; their indexed vertices and radius produce transformed conservative envelope regions. Other unsupported families have an explicitly unknown envelope, or a declared primitive bound whose coordinate basis remains unverified. Those unverified bounds never exclude a region from a query. They are coverage gaps, never transparent-space evidence. Native material identifiers have no invented acoustic absorption mapping.

`loadCollisionResource(indexPath, {expectedSHA256})` validates private index/chunk metadata and loads bounded candidate chunks only after byte-count and SHA-256 verification. The optional expected index digest comes from the export receipt; omitting it is labelled `unbound-private-index`. Its query returns both candidate triangles and intersecting unknown regions while preserving the unresolved placement labels. This is a runnable data reader, with no runtime renderer connection or startup warmup.

`placements.mjs` implements ordinary `CEntityDef` scale, inverse raw quaternion and translation. It only resolves a unique archetype plus explicit collision binding whose resource has independently established `archetype-local` coordinates. Resource names and YTYP physics-dictionary identifiers alone never establish that proof. MLO parents, CMloInstanceDef conventions, portals, active entity sets, time/LOD selection, override precedence and dynamic objects remain unresolved. Actual resource-root exports from this tool cannot pass the placement proof gate. Authored fixtures can exercise the full transform path; metadata-proven bindings remain runtime-unverified.

The installed DLL's YmapFile/YtypFile/CEntityDef/CBaseArchetypeDef/YmapEntityDef/BoundPolygonBox public properties were inspected. The publisher's [YmapFile.cs](https://github.com/dexyfex/CodeWalker/blob/master/CodeWalker.Core/GameFiles/FileTypes/YmapFile.cs) confirms that ordinary CEntityDef quaternions are inverted while MLO instances differ. `tests/Test-CodeWalkerCollisionAdapter.ps1 -CodeWalkerRoot <local-root>` checks authored skew-box vertices and four entity transform cases, including a near-unit raw quaternion, directly against that installed DLL. Its result is API/transform evidence, never a matching installed map placement.

`static-world-resource.mjs` qualifies an exterior/world identity frame only with pinned index, export receipt and resolved catalogue digests; a matching unchanged archive/source/parser; a unique native layer-zero bounds row with cache-metadata provenance; and a complete manifest/cache projection excluding interior and conditional map-group membership. It preserves GTA runtime activation as unverified. `tools/Prepare-InstalledCollisionWorld.ps1` supplies bounded, resumable offline preparation of every selected YBN, with explicit eligible/deferred states and no position/radius cutoff. Its `-PlanOnly` mode builds the complete queue without archive geometry extraction. The driver runs in PowerShell 7 and reuses the shared Windows Job supervisor; parser workers use Windows PowerShell 5.1. Native curves and interiors remain explicit gaps.

Run the portable synthetic verification with `node tests/Test-InstalledCollision.mjs`, `node tests/Test-InstalledPlacements.mjs`, `node tests/Test-StaticWorldPlacement.mjs` and `node tests/Test-WorldWarmup.mjs`. They use no GTA installation, vendor parser, network, game launch or audio endpoint.
