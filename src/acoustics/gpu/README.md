# Owned DirectCompute visibility broadphase

`AcousticGpu.cs` creates its own hardware Direct3D 11 device, compiles the embedded original `FiniteCull.hlsl`, dispatches compute and reads back completed bit masks. No game device, rendering hook, audio API, vendor library or installer is involved. This is compute-shader execution, **not DXR or RTX ray-tracing-core use**. Unsupported/software adapters fail capability detection; there is no WARP masquerading as hardware.

The GPU evaluates segment/finite-surface AABB overlap and same-side plane rejection in parallel. It returns four 32-bit potential-surface masks per segment. CPU double-precision finite-patch, convex-footprint, opening, coplanarity and unknown-region tests remain authoritative for every potential result. Masks only omit definitely clear pairs; they do not introduce new reflection points or change path/material/PCM calculations.

Coordinates must be translated to a common tile-local origin before packing. The helper bounds every component to 512 and validates finite normalized normals. The 0.005 metre broadphase margin is deliberately much wider than FP32 input/dot round-off at these coordinate magnitudes; near-plane and extent-boundary cases stay potential for exact CPU refinement. This numerical margin does not purport to be physical GTA calibration or observed surface uncertainty.

One persistent helper accepts one bounded request at a time: at most 4,096 segments and 128 finite surfaces; fixed D3D buffer ownership totals 270,352 bytes. `client.mjs` uses bounded binary frames, increasing request IDs and generation equality. Late, malformed, disconnected, wrong-generation or impossible masks reject the request. Its caller must select an explicit CPU fallback. Completed replies also undergo a real wall-clock deadline check, so delayed JavaScript timeout callbacks cannot admit a late result.

The helper waits on `IDXGIDevice2::EnqueueSetEvent` in its separate process, with a bounded deadline. It neither spins while waiting nor blocks WASAPI. Staging maps use `DO_NOT_WAIT`; GPU completion is checked before mapping. Timestamp-disjoint queries qualify upload/dispatch/copy timing; disjoint/unavailable timing is reported as unknown. CPU submission, wait, readback and total costs are separate. Process CPU accounting is cumulative as well as per-compute request; aggregate comparisons should account for Windows counter resolution.

Memory diagnostics distinguish owned buffer bytes, DXGI process local-memory CurrentUsage, helper process working set and adapter dedicated-memory capacity. Driver/runtime allocations are not silently counted as only the explicit buffers. Working-set/video-memory readings are sampled every 32 dispatches to keep diagnostics from dominating the task.

Build using `tools/Build-AcousticGpu.ps1`. `-RequireHardware` confirms real hardware capability and fails otherwise. It compiles only with the installed Framework compiler and system Windows graphics components. `node --test tests/Test-AcousticGpuDevice.mjs` runs protocol rejection fixtures everywhere and a genuine deterministic GPU-versus-exact-CPU comparison only where hardware is available. A skipped hardware case means execution is unverified on that machine.

The binary protocol is private local IPC: a length-prefixed JSON capability; 32-byte `RG82` request headers with schema/request/generation/counts/deadline, then 32-byte segments and 64-byte surfaces; 32-byte `RO82` responses with matching context, status and bounded metrics/mask byte lengths, then JSON metrics and 16 bytes of masks per segment. Only the owned helper's stdout is a result source.

Primary API references: [D3D11CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-d3d11createdevice), [CreateComputeShader](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11device-createcomputeshader), [GPU timestamp qualification](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_query_data_timestamp_disjoint), [DXGI event completion](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgidevice2-enqueuesetevent).
